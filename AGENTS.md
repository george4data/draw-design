# Notes for coding agents

This repository is built from [`docs/prd.md`](docs/prd.md). It is the single source of truth.

1. Read `docs/prd.md` §0, then your task card in §22, then only the sections the card references.
2. Runtime code lives in `skills/draw-design/scripts/ddraw/`. It is **Python ≥ 3.10, standard library only**, type-hinted, and must pass `ruff` and `mypy --strict`.
3. Never edit `reference/` (git-ignored, read-only; re-create with `scripts/fetch-references.sh`). Never import from it.
4. Never hand-edit generated blocks (`<!-- BEGIN GENERATED:… -->`) or `data/shapes/*` (built by `make shapes`). Run the generator instead.
5. A new diagram type adds **only its own files**: `data/types.d/<slug>.json`, `scripts/ddraw/layout/types/<slug>.py`, `references/type-<slug>.md`, `examples/<slug>.dd.json`, and its tests. Shared tables are regenerated by scripts, so agents can build types in parallel.
6. Run `make check` (ruff, mypy, pytest, docs checks) before committing.
7. Don't bump versions or edit manifest versions; `main` bumps after merge.
8. When the PRD is silent or wrong: add an ADR in `docs/decisions/` or an `OQ-xx` in PRD §24 in the same change, and pick the conservative option.

Useful commands:

```bash
make venv        # create .venv with dev tools (uv)
make check       # lint + types + tests
make gallery     # build every example into gallery/
make render      # gallery + PNGs (needs draw.io Desktop)
make shapes      # rebuild the vendor icon catalog from the pinned index, verified with draw.io Desktop
skills/draw-design/bin/ddraw build skills/draw-design/examples/architecture.dd.json -o /tmp/a.drawio
```
